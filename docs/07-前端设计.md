# 07 · 前端设计（路由 / 页面 / 状态 / 组件）

> 版本 v1.0（2026-10-15）。Vue 3 + Vite + TypeScript + Vue Router + Pinia + Tailwind CSS。
> 设计基调：暗色系演出氛围 + 高对比信息层级（对标 Bestdori 的信息密度，交互对标网易云）。

## 1. 目录结构约定

```
frontend/src/
├── api/            # axios 实例 + 按模块的接口封装（auth/song/event/order/...）
├── stores/         # Pinia：authStore / playerStore / assistantStore
├── router/         # 路由表 + 守卫
├── layouts/        # UserLayout（含全局播放器）/ AdminLayout（侧边栏）
├── views/          # 页面组件（与路由一一对应）
├── components/     # 通用组件：Pagination / EmptyState / StatusBadge / CountdownTimer ...
└── utils/          # request 拦截器（token 注入、401 跳转、错误码→提示文案）
```

## 2. 路由表与守卫

| 路径 | 页面 | 访问控制 |
|---|---|---|
| `/` | 首页（近期演出 + 新曲推荐） | 公开 |
| `/songs` `/songs/:id` | 歌曲库 / 歌曲详情 | 公开 |
| `/events` `/events/:id` | 演出列表 / 演出详情（含票档） | 公开 |
| `/login` `/register` | 登录 / 注册 | 公开（已登录访问则跳首页） |
| `/checkout/:orderNo` | 购票确认 + 支付倒计时 | 登录 |
| `/my/orders` `/my/orders/:orderNo` | 我的订单 / 订单详情（电子票） | 登录 |
| `/my/favorites` `/my/playlists` `/my/playlists/:id` | 收藏 / 歌单 | 登录 |
| `/profile` | 个人中心 | 登录 |
| `/admin` 及子路由 | 后台（Dashboard/歌曲/演出/订单/用户） | ADMIN |

**守卫规则**：
- `requiresAuth`：无 token → 跳 `/login` 并携带 `redirect` 参数，**登录成功后回到来源页**
- `requiresAdmin`：非 ADMIN 角色 → 403 页
- 游客在歌曲页点播放：不跳转，弹登录引导 Dialog（文案："登录后即可播放"，两个按钮：去登录 / 随便逛逛）

## 3. 页面明细与关键交互

### 3.1 首页 `/`
- 区块：Hero 轮播（在售演出海报，点击进详情）｜近期演出卡片（4 场）｜新曲推荐（8 首，封面网格）
- 空态：无在售演出时显示"暂无在售演出，看看往期 →"

### 3.2 歌曲库 `/songs`
- 筛选栏：乐队 Tab（全部/MyGO/Ave Mujica）｜专辑下拉｜标签多选｜搜索框（防抖 300ms）
- 歌曲卡片：封面 + 标题 + 专辑 + 时长 + 播放按钮悬浮；点击行进详情，点击播放钮直接入播放队列
- 分页：页码组件；URL 同步筛选参数（可分享、可回退）

### 3.3 歌曲详情 `/songs/:id`
- 左侧大封面 + 播放大按钮；右侧元信息（乐队/专辑/发行日期/时长/标签）
- MV 区：按 `mvPlatform` 渲染 B 站 iframe embed（`//player.bilibili.com/player.html?bvid=...`）或跳转按钮
- **兜底**：`audioUrl` 为空 → 播放按钮禁用并提示"暂无试听，观看 MV"；embed 加载失败 → 显示"前往 B 站观看"外链

### 3.4 演出详情 `/events/:id`（购票入口，最重页面）
- 头部：海报 + 标题 + 乐队徽标 + 场馆 + 状态徽标（DRAFT 对用户隐藏）
- 场次 Tab（昼场/夜场…）→ 每场下列票档表格：

| 票档 | 单价 | 状态 | 操作 |
|---|---|---|---|
| S席 | ¥980 | 余票紧张（≤10% 时黄色） / 售罄（灰色禁用） | 数量选择器(1~maxPerUser) + 立即购买 |
| 普通席 | ¥480 | 充足（绿色） | 同上 |

- 点击购买：未登录先弹登录引导；已登录 → `POST /orders` → 成功跳 `/checkout/:orderNo`；40901 → 票档行内红字提示"仅剩 N 张"并刷新余票

### 3.5 购票确认 `/checkout/:orderNo`
- 信息卡：演出名/场次/票档/数量/单价快照/合计
- **支付倒计时**（15:00 递减）：以服务端 `payDeadline` 为准换算，前端时钟仅展示；归零 → 轮询刷新订单状态 → 显示"已超时"
- 按钮：模拟支付（调 pay 接口，成功 → 电子票页）/ 取消订单（二次确认 Dialog）

### 3.6 我的订单 `/my/orders`
- 状态 Tab：全部/待支付/已支付/已取消；每单卡片可跳详情
- 待支付订单卡片上常驻小倒计时

### 3.7 订单详情（电子票）`/my/orders/:orderNo`
- 票券视觉（大号 orderNo + 演出信息 + 票档数量 + 二维码占位[码内容=orderNo，P2 再做真扫码]）
- 按状态显示操作：待支付→去支付/取消；已支付→申请退款入口（提交后走管理员审核）

### 3.8 管理端 `/admin/*`
- AdminLayout：左侧菜单（看板/歌曲/演出/订单/用户），顶部面包屑
- Dashboard：四张指标卡（今日销售额/今日订单/本月销售额/在售演出）+ ECharts 折线（30天趋势）+ 饼图（票档销量占比）
- 演出管理：列表（状态徽标）→ 编辑页 = 基本信息 + 场次子表 + 每场次票档子表（嵌套编辑；NOT_OPEN 才可改库存）+ "发布"按钮（校验不过则 toast 具体原因）
- 订单管理：筛选区（状态/订单号/用户/演出）+ 表格 + 退款 Dialog（理由必填）
- 表格页统一：loading skeleton / 空态 / 错误重试三态

## 4. 全局组件与状态

### 4.1 AppPlayer（全局底部播放条，挂 UserLayout）
- playerStore（Pinia）：`{ queue: [], currentIndex, isPlaying, currentTime, duration, volume }`
- 功能：播放/暂停、进度拖拽、音量、上一首/下一首、队列抽屉（可删除/清空）
- 来源动作：歌曲卡片播放钮（单曲入队并播）、歌单"全部播放"、详情页播放
- 未登录点击播放 → 登录引导 Dialog；音频 error 事件 → toast"音源失效"并自动跳下一首

### 4.2 AssistantWidget（AI 悬浮窗，M7）
- 右下角悬浮球 → 展开聊天面板；SSE 流式渲染；会话历史存 localStorage
- 后端 503 时显示"AI 助手离线"+ FAQ 列表，悬浮球置灰

### 4.3 通用组件
`StatusBadge`（演出/场次/订单状态→颜色映射表统一一处）、`CountdownTimer`（输入目标时间，emit 归零事件）、`Pagination`、`EmptyState`（图标+文案+行动按钮）、`ConfirmDialog`

## 5. 页面状态规范（每个列表/详情页必须实现四态）

| 状态 | 表现 |
|---|---|
| Loading | 骨架屏（与最终布局一致，不用转圈遮全屏） |
| Success | 正常渲染 |
| Empty | EmptyState 组件 + 引导动作（如"去看演出日历"） |
| Error | 错误插画 + 重试按钮；401 自动走登录流程 |

## 6. 请求层规范（utils/request）

- axios 拦截器：请求带 token；响应拦截统一解 `{code,message,data}`
- `code === 0` → 直接返回 data；`40101` → 清 token 跳登录；`40901/40902/40903` → 业务 toast（表单场景透传 message）；`50001` → 全局 toast"服务开小差了"
- 环境变量：`VITE_API_BASE`（.env.development 指向 `http://localhost:8080/api/v1`，生产 `/api/v1` 走 Nginx 反代）
