# 上线前检查清单（生产加固）

> 对应代码：`config/RateLimitFilter`、`config/SecurityConfig`、`common/ReadinessController`、`scripts/backup-db.bat`
> 全部项已通过测试（`HardeningConfigTest` / `ReadinessApiTest`）与真实启动验证。

## 一、必须改的环境变量

| 变量 | 说明 | 示例 |
|---|---|---|
| `CORS_ALLOWED_ORIGINS` | 正式域名，逗号分隔；**不能留 localhost** | `https://bangdream-live.example.com` |
| `DB_URL` / `DB_USERNAME` / `DB_PASSWORD` | 生产库连接（密码走密钥管理，不进仓库） | — |
| `JWT_SECRET` | ≥32 字节随机串，**必须换掉开发值** | `openssl rand -base64 48` |
| `LOG_LEVEL` | 生产 `INFO`；排查时临时 `DEBUG` | `INFO` |
| `SQL_LOG_LEVEL` | 生产 `WARN`（避免打印 SQL 与参数） | `WARN` |
| `RATE_LIMIT_ENABLED` | 默认 `true`；压测/内网可关 | `true` |
| `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` | 助手接真实模型；缺省走本机 Ollama | — |

## 二、探针

| 端点 | 用途 | 正常响应 |
|---|---|---|
| `GET /api/v1/health` | 存活探针（进程活着即可） | `200 {"status":"UP"}` |
| `GET /api/v1/ready` | 就绪探针（含 DB `SELECT 1`） | `200 {"status":"UP","db":"UP"}`；DB 挂 → `503` |

## 三、限流阈值

| 分组 | 阈值（每分钟/每 IP） |
|---|---|
| `/api/v1/auth/login`、`/auth/register` | 10 |
| `/api/v1/orders`（下单） | 20 |
| `/api/v1/assistant/**` | 20 |
| 其他接口 | 120 |

命中返回 `429 {"code":42901,"message":"请求过于频繁，请稍后再试"}`。
> 单机内存计数；多实例部署需换 Redis 令牌桶（替换点在 `RateLimitFilter.allow`）。

## 四、备份

```bash
set DB_USERNAME=bandori
set DB_PASSWORD=****
set MYSQL_BIN=C:/Program Files\MySQL\MySQL Server 8.0\bin
scripts\backup-db.bat
```

- 输出：`backups/bandori_live_YYYYMMDD_HHMMSS.sql`
- 自动清理 7 天前文件（`forfiles /d -7`）
- 建议用 Windows 任务计划程序每天 03:00 执行

## 五、部署后自检

1. `curl https://<域名>/api/v1/ready` → `db: UP`
2. 浏览器打开前端，Network 里 API 响应头含 `Access-Control-Allow-Origin: <你的域名>`
3. 连续 11 次错误登录 → 第 11 次 `429`
4. 启动日志中**不应**再出现 `Using generated security password`
5. 备份脚本跑一次，确认 `backups/` 下有文件且能 `mysql < file.sql` 恢复到空库
