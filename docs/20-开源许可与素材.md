第三方内容、依赖包、商标和字体依照各自权利声明，不随项目代码获得 MIT 授权，见 NOTICE.md。

## 默认分发范围

此前 Git 跟踪的 MV、首帧、封面、立绘、标识、favicon 和含这些素材的页面截图，
缺少可核实的分发授权记录，现从当前 Git 跟踪中移除。本机文件保留并忽略，不自动删除，
不将未知来源填写成已获授权。逐文件路径、大小和 SHA-256 见 assets-manifest.csv。
清单中 source_url 为空代表没有可核实的逐文件来源，permission_evidence 为空代表没有授权证据。
截图由项目生成，所包含第三方画面的权利仍未核实。

默认 Vite 开发与构建关闭 publicDir，因此即使本机仍有素材，默认构建也不会打包。
首页视频、海报、标识和封面缺失时使用渐变与文字降级。GitHub CI 使用此默认模式。

## 替换流程

1. 使用自己制作或已明确获准公开展示、分发的图片和视频；逐文件记录来源链接、权利方、
   许可文本/授权证据、适用范围及 SHA-256，更新清单后再决定是否加入版本控制。
2. 本地素材路径：封面 frontend/public/img/covers/，标识 frontend/public/img/logo/，
   其余乐队和成员图使用数据库中的本地路径；Hero 为 frontend/public/assets/band-{mygo|mujica}-720p.mp4，
   可选首帧为 band-{mygo|mujica}-poster.jpg。保留同路径即可替换，无需修改冻结迁移。
3. 确认使用权后，仅在当前命令的进程环境设置 INCLUDE_LOCAL_ASSETS=1 再运行 npm run dev/build。
   PowerShell 示例：$env:INCLUDE_LOCAL_ASSETS='1'；Bash 示例：INCLUDE_LOCAL_ASSETS=1 npm run build。
   开启后 public 中的本地文件会被提供给浏览器或复制到 dist，公开部署前必须检查其内容。
4. 管理端上传仅供上传者有权使用的 MP4；应用不会判断内容权利，也不自动下载、转码或更新首帧。
   Ubuntu 上传目录为 var/hero-assets，默认部署不复制本机 Hero 文件；显式启用素材后才初始化缺失槽位。

官方试听、播放器和外部站点链接仍由浏览器直接访问原站，不视作本站取得素材再分发授权。
Google Fonts 在浏览器端外链加载；若离线自托管字体，须另附对应字体许可证。
默认构建后可运行 `python scripts/check-assets.py --dist`；CI 同样检查未核实素材未被重新跟踪或打入产物。

## 历史与发布限制

此次仅从当前版本移除素材，旧 Git 提交仍可能包含这些文件。没有重写历史或强制推送。
如要让公开仓库所有历史版本也不携带这些文件，发布前需选择新建只含当前代码的仓库，
或在单独备份与协作协调后进行历史清理；这不由普通修复提交自动完成。
新克隆默认可运行无本地素材界面。Ubuntu/Nginx 实际部署、公开平台条款与具体素材许可由发布时验收。
