# 12 · 前端提示词：小灯助手界面升级（悬浮球 → 大面板）

> 用途：粘贴给前端会话直接开发。
> 只改前端展示与交互，**后端接口不动**（`/api/v1/assistant/**` 契约见 [06 接口设计](06-接口设计.md)）。
> 现状基线：`frontend/src/components/AssistantWidget.vue`（380px × min(560px,70vh) 窄抽屉，纯文本气泡）

---

## 一、目标

现在的小灯像"网页右下角的小挂件"，目标是让它像**真正的 AI 助手面板**：

1. **够大**：默认 720 宽，可一键最大化，手机端全屏
2. **够专业**：时间戳、复制、重试、停止生成、快捷提问、会话留存
3. **不打断**：用户往上翻历史时不要被自动滚动拽回底部
4. **不改后端**：所有能力基于现有 SSE 接口与本地状态

---

## 二、尺寸与布局

### 2.1 三种尺寸状态

| 状态 | 尺寸 | 触发 |
|---|---|---|
| 常规（默认） | `720px × min(820px, 82vh)`，右下角 `right-6`，底部避让播放条 | 打开面板 |
| 最大化 | `min(1200px, 92vw) × 90vh`，居中（`inset` 居中或 `right-6`+宽度） | 点右上角 ⛶ |
| 收起 | 只留悬浮球（现有行为不变） | 点 ✕ / Esc |

移动端（< 640px）：**全屏** `100dvw × 100dvh`，无圆角，输入区避开安全区（`env(safe-area-inset-bottom)`）。

## 三、功能清单（按优先级）

### P0 —— 必须做

| # | 功能 | 说明 |
|---|---|---|
| 1 | 三态尺寸 | 常规 / 最大化 / 收起；最大化状态用 `ref` 记录，不落盘 |
| 2 | 消息时间戳 | 每条消息记 `at: Date.now()`，气泡右下角显示 `HH:mm`；跨天插入「今天 / 昨天 / 10月30日」分隔条 |
| 3 | 复制回复 | 助手气泡 hover 出现 ⧉，`navigator.clipboard.writeText`，成功后按钮变「已复制」1.5s |
| 4 | 停止生成 | 流式中显示「⏹ 停止生成」，调用现有 `AbortController.abort()`；已生成内容保留 |
| 5 | 发送失败可重试 | 失败气泡下方显示「重试」，重试复用同一条消息（不要重复 push 用户气泡） |
| 6 | 快捷提问 | 空会话时展示 3-4 个 chips（推荐演出 / 某首歌的专辑 / 乐队成员 / 怎么买票），点击即发送 |
| 7 | 智能自动滚动 | 仅当用户**贴底**（距底 < 80px）时自动滚；否则显示「↓ 回到底部」浮标 |
| 8 | 输入框 | `textarea` 自动增高（1~5 行，`max-h` 对应），显示字数 `n/500`，超限禁用发送 |
| 9 | 键盘 | Enter 发送 / Shift+Enter 换行 / Esc 关闭面板；打开时焦点落到输入框 |
| 10 | 移动端全屏 | < 640px 全屏 + 安全区；悬浮球不被遮挡 |
| 11 | 可访问性 | 消息区 `aria-live="polite"`；悬浮球/关闭/最大化按钮均有 `aria-label`；焦点不跑丢 |

### P1 —— 应该做

| # | 功能 | 说明 |
|---|---|---|
| 12 | 会话留存 | `sessionStorage` 按人格分 key（`assistant:msgs:xiaodeng`），存最近 50 条；刷新后恢复；**不要持久化 token** |
| 13 | 清空二次确认 | 点「清空」弹出轻量确认（`confirm()` 也可以，但更推荐行内二次点击：再点一次才清） |
| 14 | 重新生成 | 助手最后一条消息下方「重新生成」，删除该条后重发上一条用户消息 |
| 15 | 长回复折叠 | 超过 12 行且非流式时，「展开全文 / 收起」 |
| 16 | 纯文本排版 | 不引入 markdown 库，但要做轻量排版：换行 → `<br>`、行首 `- ` → 列表点、`1. ` → 序号、`**粗体**` 可选（用正则替换为 `<strong>` 时必须转义 HTML，**禁止 v-html 直接渲染原始文本**） |
| 17 | 消息状态 | 用户消息右侧显示 发送中（灰点）/ 已发送 / 失败（红点） |

### P2 —— 可选

- 字号切换（小/中/大，localStorage 记忆）
- 面板尺寸拖拽（右下角 resize handle）
- 「↑」键编辑上一条用户消息

## 四、组件拆分（单文件别超 450 行）

建议拆成（都在 `src/components/assistant/` 下）：

```
assistant/
├── AssistantWidget.vue      ← 只负责：悬浮球 + 开关 + 尺寸三态 + 组合
├── AssistantHeader.vue      ← 头像/人格名/在线态/最大化/关闭 + 人格 chips + 清空
├── MessageList.vue          ← 日期分隔、消息循环、自动滚动策略、回到底部浮标
├── MessageBubble.vue        ← 单条：头像、气泡、时间、复制、重试、折叠、轻量排版
└── AssistantComposer.vue    ← 快捷提问 chips + 自适应 textarea + 字数 + 发送/停止
```

状态集中在 `AssistantWidget.vue`，用 `provide/inject` 或 props+emit 下发（不引入 Pinia 新 store，除非你认为确实更清晰）。

## 五、状态设计（照这个走，避免踩坑）

```js
// 每个会话（人格）独立
const threads = reactive({
  xiaodeng: { messages: [], loading: false, error: '', controller: null },
  anon:     { messages: [], loading: false, error: '', controller: null },
  sakiko:   { messages: [], loading: false, error: '', controller: null },
  mutsumi:  { messages: [], loading: false, error: '', controller: null },
})
const persona = ref('xiaodeng')
const open = ref(false)
const maximized = ref(false)
const stickToBottom = ref(true)   // 只有它为 true 才自动滚
```

消息结构：

```js
{ role: 'user' | 'assistant', text, at: Date.now(),
  streaming?: boolean, error?: string, status?: 'sending' | 'sent' | 'failed' }
```

**关键取舍**：`stickToBottom` 由滚动事件维护（`scrollHeight - scrollTop - clientHeight < 80`），不要用「有新消息就滚」的粗暴逻辑，否则用户看历史时会被反复拽回底部。

## 六、边界与错误

| 场景 | 处理 |
|---|---|
| 401 登录失效 | 沿用现有 `request.js` 的 `handleUnauthorized`；面板内提示「登录已过期，请重新登录」并可跳登录 |
| SSE 不可用 | 沿用现有降级：catch 后调普通接口 `/assistant/chat`，气泡上方加一条系统提示「网络不稳，已切换普通模式」 |
| 连续快速发送 | `loading` 期间禁用发送；Enter 连按不叠加请求 |
| 空消息/纯空白 | 不发送 |
| 超长输入 | > 500 字禁用发送并显示计数红色 |
| 流式被中断（切人格/关闭面板） | 保留已生成内容，标记 `streaming: false`；不要清除消息 |
| 人格切换 | 各人格独立消息、独立 loading；切换回来恢复现场（现有逻辑已如此，别改坏） |
| 播放条出现 | 保留现有避让：`player.current && !player.barCollapsed ? bottom-[10.5rem] : bottom-[6.5rem]` |

## 七、明确不做

- 不引入新依赖（markdown 渲染库、emoji 选择器、UI 组件库一律不加）
- 不改后端接口（不加"多会话列表"这类需要服务端支持的功能）
- 不做语音输入、不做图片上传（后端无对应能力）
- 不要用 `v-html` 渲染模型返回的原始文本（XSS 面）

## 九、给实现者的两条提醒

1. **别动 SSE 封装**：现有 `chatStream()` 用原生 fetch（没有 axios 的 10s 超时问题），但一定要把 `AbortController` 透传到最后一条消息，否则「停止生成」会失效。
2. **排版安全**：轻量排版时若要输出 HTML，先 `escapeHtml` 再替换 `\n`/列表/粗体，或干脆只用 CSS `white-space: pre-wrap` + 行首缩进，宁可朴素也不要引入 XSS 面。
