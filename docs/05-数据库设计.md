# 05 · 数据库设计（字段级）

> 版本 v1.0（2026-10-15）。MySQL 8.x / InnoDB / utf8mb4_general_ci。
> 定稿后按本文档编写 `sql/V1__init.sql`（Flyway 版本化）。

## 1. 全局约定

- 主键：`id BIGINT UNSIGNED AUTO_INCREMENT`
- 时间：`created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP`、`updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP`
- 软删除：业务表带 `is_deleted TINYINT NOT NULL DEFAULT 0`（订单/日志类数据除外，只改状态不物理删）
- 金额：`DECIMAL(10,2)`，**禁止 FLOAT/DOUBLE 存钱**
- 枚举字段一律 VARCHAR(20) 存大写英文常量（可读性好于 TINYINT），常量在代码中定义为枚举类
- 外键：**不建物理外键约束**（企业惯例，靠应用层保证），只建索引；用注释标明逻辑关联

## 2. 表清单与 ER 关系概览

```
band 1───n album
band 1───n member
band 1───n song n───1 album
live_event 1───n live_session 1───n ticket_type
live_event 1───n ticket_order n───1 ticket_type（session 冗余 event_id）
user 1───n ticket_order / favorite / playlist
playlist 1───n playlist_item n───1 song
live_session 1───n setlist_item n───1 song
user 1───n comment（P2）
```

共 13 张表：`user`、`band`、`album`、`member`、`song`、`live_event`、`live_session`、`ticket_type`、`ticket_order`、`favorite`、`playlist`、`playlist_item`、`setlist_item`（`comment` 为 P2 预留）。

## 4. 状态机（必须严格按图流转）

### 4.1 场次状态（定时任务驱动）

```
NOT_OPEN ──(到达 sale_start_time，任务每分钟扫)──→ ONSALE
ONSALE  ──(到达 end_time，任务扫)──→ ENDED
SOLD_OUT：不落库，查询时 available_stock = 0 派生
```

### 4.2 订单状态（核心）

```
                    ┌────────────(管理员退款)────────────┐
                    │                                    ▼
PENDING_PAYMENT ──(模拟支付)──→ PAID ────────────────→ REFUNDED
      │ │
      │ └──(用户主动取消)──→ CANCELLED
      └────(pay_deadline 超时，任务扫)──→ EXPIRED
```

| 流转 | 触发方 | 前置校验 | 副作用 |
|---|---|---|---|
| 创建 → PENDING_PAYMENT | 用户 | 场次 ONSALE、票档启用、qty ≤ max_per_user、余票足够 | **同一事务内** sold_count + qty |
| PENDING → PAID | 用户（模拟支付） | 本人订单、状态 PENDING、未过 pay_deadline | 记 paid_at；接口幂等：重复支付返回原结果不报错 |
| PENDING → CANCELLED | 用户 | 状态 PENDING | sold_count − qty（保证不为负），记 cancelled_at |
| PENDING → EXPIRED | 定时任务（每分钟） | status=PENDING AND pay_deadline < NOW() | sold_count − qty，记 cancelled_at |
| PAID → REFUNDED | 管理员 | 演出 start_time 未到 | sold_count − qty，必填 refund_reason |

## 5. 业务规则清单（实现与测试都必须逐条对照）

1. **防超卖（P0 核心）**：扣减库存必须用原子 SQL：
   `UPDATE ticket_type SET sold_count = sold_count + #{qty} WHERE id = #{id} AND status=1 AND sold_count + #{qty} <= total_stock`
   影响行数 = 0 即库存不足，返回 409。禁止"先 SELECT 再 UPDATE"。
2. **扣库存与建订单必须在同一事务**（`@Transactional`），任一失败整体回滚。
3. **下单限购**：同一 user + 同一 session 下"非已取消"状态的订单 quantity 合计 ≤ max_per_user。
4. **价格快照**：订单存下单时单价；票档改价只影响未来订单。
5. **超时取消**：定时任务 1 分钟一轮；因任务延迟造成的"超时后仍支付成功"由支付接口的 pay_deadline 校验兜底。
6. **退款回滚库存**：`UPDATE ... SET sold_count = sold_count - #{qty} WHERE id=#{id} AND sold_count >= #{qty}`，影响行数为 0 记 ERROR 日志并告警（理论上不该发生）。
7. **删除策略**：歌曲/演出等支持软删；已有关联订单的演出**禁止物理删除**，只允许 CANCELLED。
8. **权限**：所有 `/admin/**` 接口要求 ADMIN 角色；订单详情仅本人与 ADMIN 可见。
9. **游客可见范围**：songs/events/sessions 列表与详情公开；下单、收藏、歌单需登录。
