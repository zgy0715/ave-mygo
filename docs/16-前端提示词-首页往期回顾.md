## 二、要做什么

在首页（「近期演出」区块之后）新增一块 **「往期回顾 / PAST LIVES」**，展示最近 4 场已结束的演出。

### 2.1 数据获取（独立请求，不复用现有 6 条）

```js
// 新增一个独立请求，按状态精确取
const pastResp = await listEvents({ status: 'ENDED', pageSize: 12 })
```

**为什么取 12 条再截 4**：列表接口默认按 id 倒序，但 id 顺序不等于演出时间顺序（中途补录过历史数据）。
要对齐「最近结束」的顺序，需要拿到场次时间再排序：

```js
async function loadPast() {
  const resp = await listEvents({ status: 'ENDED', pageSize: 12 })
  const list = resp.content || []
  // 并发取详情拿最后一场的日期（最多 12 个请求，可接受；已在 EventsView 有过同样做法）
  const withDate = await Promise.all(
    list.map(async (ev) => {
      try {
        const d = await getEvent(ev.id)
        const times = (d.sessions || []).map((s) => s.startTime).filter(Boolean).sort()
        return { ...ev, lastSessionAt: times.length ? times[times.length - 1] : null }
      } catch {
        return { ...ev, lastSessionAt: null }
      }
    }),
  )
  past.value = withDate
    .sort((a, b) => String(b.lastSessionAt || '').localeCompare(String(a.lastSessionAt || '')))
    .slice(0, 4)
}
```

## 五、给实现者的提醒

1. `listEvents` 的返回是分页对象，列表在 `data.content`，总数在 `data.totalElements`（现有 `request.js` 已剥外壳）。
2. `ENDED` 的 `nextSessionTime` 是 `null`，**不要拿它当日期显示**，要用详情接口里的 `sessions[].startTime`。
3. 12 个 detail 请求听起来多，但这些响应都很小且有浏览器缓存；如果你觉得不优雅，可以只在截取后的 4 场上补查——顺序先用 id 倒序近似，标注 TODO 即可。
