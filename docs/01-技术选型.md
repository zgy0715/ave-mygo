# 01 · 技术选型

## 已确定

| 项 | 结论 | 说明 |
|---|---|---|
| 数据库 | **MySQL 8.x** | 企业主流关系型库；统一用 `utf8mb4` 字符集；建表脚本统一放 `sql/` |
| 前端框架 | Vue 3（拟） | 与现有学习路线一致（HTML/CSS/JS → Tailwind → Vue） |
| 前端构建 | Vite 5+ | 事实标准 |
| UI 方案 | Tailwind CSS 3+ | 配合组件库按后端选型再定 |

## 待定（方向定了之后必须先敲定）

### 后端三选一

| 候选 | 优势 | 代价 | 适合场景 |
|---|---|---|---|
| Node.js (Express/NestJS) | 全 JS 技术栈，前后端心智统一，上手最快 | 企业级规范生态弱于 Java | 想快速出活、专注前端成长 |
| Java Spring Boot | 企业主流，权限/事务/ORM 生态最成熟，简历含金量高 | 学习曲线陡，样板代码多 | 面向后端岗位/大厂简历 |
| Python FastAPI | 接口开发极快，文档自动生成 | 异步/工程化规范需自律 | 数据处理+接口混合场景 |

> 建议：若目标是**就业简历**选 Spring Boot；若目标是**快速走通全栈闭环**选 Node.js。

### 随后端联动的选型

- ORM：Node→Prisma / Java→MyBatis-Plus 或 Spring Data JPA / Python→SQLAlchemy
- 鉴权：JWT + Spring Security / JWT + 中间件（Node/Python）
- 接口文档：OpenAPI（Swagger UI / Knife4j）
- 部署：Docker Compose（app + mysql + nginx）

## 原则

1. **先定方向，再锁栈**：技术栈服务于业务方向，不为练技术而练技术。
2. **一切配置进版本库**：数据库密码等敏感信息走 `.env`（gitignore）+ `.env.example` 模板。
3. **接口先行**：前后端并行开发前，先用接口文档（OpenAPI）约定契约。
