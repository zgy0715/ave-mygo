## 二、接口契约

### 2.1 请求

```
POST /api/v1/assistant/chat/v2
Content-Type: application/json
Authorization: Bearer <token>   ← 可选：游客也能用（只读能力）

{ "message": "把迷星叫的 MV 换成 https://…", "conversationId": "c-xxx" }
```

- `message`：≤ 500 字，空则 40001
- `conversationId`：**面板打开时生成一次，整页复用**（后端用于多轮上下文）
- 身份由 token 决定：无 token / 非管理员 → 后端只给只读工具；管理员 → 给全部 15 个工具

### 2.2 响应：`text/event-stream`，每帧 `data: {json}`

| type | 字段 | 前端渲染 |
|---|---|---|
| `status` | `phase: "thinking"` | 三点动画 / 「思考中…」 |
| `delta` | `text` | 追加到气泡（真打字机，**不要做二次假打字**） |
| `tool` | `name`, `status: RUNNING\|OK\|FAIL`, `summary` | 灰色条目：`🔧 正在查歌曲…` → `🔧 已查歌曲` |
| `confirm` | `token`, `toolName`, `title`, `arguments`, `preview` | 琥珀确认卡片（标题用 `title`，**它已经是人类可读的**，如「《迷星叫》 的 MV 地址」） |
| `done` | `usedTools`, `conversationId`, `elapsedMs`, `pending?` | 收尾（`pending: true` 表示等用户确认） |
| `error` | `code`, `message` | 提示（50301 = LLM 未就绪） |

### 2.3 真实抓包样本（照这个写解析）

```
data: {"type":"status","phase":"thinking"}
data: {"type":"tool","name":"search_songs","status":"RUNNING","summary":"正在查歌曲…"}
data: {"type":"tool","name":"search_songs","status":"OK","summary":"共 1 首：- id=1 《迷星叫》 …"}
data: {"type":"delta","text":"《春日影》出自"}
data: {"type":"delta","text":"专辑《迷跡波》。"}
data: {"type":"done","usedTools":1,"conversationId":"v2-q1","elapsedMs":10203}
```

写操作时（无 delta，直接 confirm）：

```
data: {"type":"confirm","token":"8f3c…","toolName":"update_song_mv",
       "title":"《迷星叫》 的 MV 地址","arguments":{"songId":1,"mvUrl":"https://…"},
       "preview":"《迷星叫》 的 MV 地址 → mvUrl=https://…，songId=1"}
data: {"type":"done","usedTools":1,"conversationId":"v2-q2","pending":true,"elapsedMs":9600}
```

### 2.4 确认接口（不变，复用现有）

```
POST /api/v1/admin/agent/confirm   { "token": "8f3c…", "approve": true|false }
→ { "code":0, "data": { "status":"EXECUTED|REJECTED|FAILED", "result":"…" } }
```
> 确认后**不要**再调 v2 让模型复述（省 10 秒），直接本地把卡片改成「✅ 已执行」并展示 `result`。

### 3.1 解析要点（照抄）

```js
const res = await fetch(`${base}/assistant/chat/v2`, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json', ...(token ? { Authorization: `Bearer ${token}` } : {}) },
  body: JSON.stringify({ message, conversationId }),
  signal,
})
if (!res.ok || !res.body) throw new Error(`stream failed: ${res.status}`)

const reader = res.body.getReader()
const decoder = new TextDecoder()
let buffer = ''
while (true) {
  const { value, done } = await reader.read()
  if (done) break
  buffer += decoder.decode(value, { stream: true })
  const frames = buffer.split('\n\n')
  buffer = frames.pop() || ''
  for (const frame of frames) {
    const line = frame.split('\n').find((l) => l.startsWith('data:'))
    if (!line) continue
    const evt = JSON.parse(line.slice(5).trim())
    switch (evt.type) {
      case 'status': /* 显示思考中 */ break
      case 'delta':  /* bubble.text += evt.text */ break
      case 'tool':   /* push 工具条目 */ break
      case 'confirm':/* push 确认卡片 {token, title, arguments, preview} */ break
      case 'done':   /* 收尾，记录 elapsedMs */ break
      case 'error':  /* 提示 evt.message */ break
    }
  }
}
```

**注意**：v2 是普通 POST 流，**没有 10 秒超时问题**（fetch 流不受 axios timeout 影响），但请求可能持续 20~30 秒，别自己套 5s/10s 的 abort 计时器；只在用户点「停止」时 abort。

## 四、行为变化（产品视角）

| 场景 | v1 现在 | v2 之后 |

| 游客问「有几场演出」 | 走规则兜底/固定文案 | 真查库回答，首字 ~1s |

| 纯寒暄「你好」 | 走 SSE，规则回复 | 走快速通道，**不挂工具**（省 3~6s） |

## 六、两个坑（后端已踩过，前端别重犯）

1. **不要用 EventSource**：v2 是 POST，EventSource 只支持 GET。用 fetch + ReadableStream。
2. **不要自己给流式请求设短超时**：一次请求最长可能 30s（工具多轮），设 5s/10s 会看起来"经常失败"。用户点停止才 abort。
