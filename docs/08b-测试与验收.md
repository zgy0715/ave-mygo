## 2. 核心自动化用例（P0 必做）

### 2.1 购票防超卖（最高优先级）

| # | 场景 | 步骤 | 预期 |
|---|---|---|---|
| T01 | 正常下单 | 余票 50，用户 A 下单 2 张 | 200，sold_count=2，订单 PENDING，金额=单价×2 |
| T02 | **并发超卖** | 余票 1，两线程同时各下单 1 张 | 恰好 1 个 200、1 个 409/40901；sold_count=1，total 不变 |
| T03 | 超限购 | max_per_user=4，用户已购 3，再下单 2 | 409/40903，库存不变 |
| T04 | 库存快照扣减 | 下单 2 张后立即查详情 | availableStock 减少 2（事务提交后可见） |
| T05 | CHECK 兜底 | 直接 SQL 强行 UPDATE sold_count 超过 total | 数据库报错（约束生效证明） |

### 2.2 订单状态机

| # | 场景 | 前置 | 预期 |
|---|---|---|---|
| T10 | 模拟支付成功 | PENDING 未超时 | PAID，paid_at 落库，库存不变 |
| T11 | 重复支付幂等 | 已 PAID 再调 pay | 返回 200 + PAID（不报错不重复扣款） |
| T12 | 超时后支付 | pay_deadline 已过 | 40902；订单已被任务置 EXPIRED |
| T13 | 用户取消 | PENDING → cancel | CANCELLED，sold_count 回滚，available 恢复 |
| T14 | 超时任务 | 造数据 pay_deadline=过去 1 分钟，跑任务 | EXPIRED + 库存回滚；PAID 订单不受影响 |
| T15 | 管理员退款 | PAID、演出未开演 | REFUNDED，refund_reason 必填，库存回滚 |
| T16 | 开演后退款 | 演出 start_time 已过 | 40902 拒绝 |
| T17 | 越权 | 用户 A 查/取消用户 B 订单 | 40401（不泄露存在性） |

## 3. 手动回归清单（M6 上线前过一遍）

- [ ] 游客旅程：首页 → 歌曲 → 点播放 → 登录引导 → 注册 → 回原页播放（docs/04 §9 旅程 A 全程）
- [ ] 购票旅程：选场次 → 409 提示 → 改数量 → 下单 → 倒计时 → 支付 → 电子票
- [ ] 超时旅程：下单不支付 → 等 15 分钟（或临时把 deadline 调短）→ 订单变 EXPIRED → 余票恢复
- [ ] 管理旅程：建演出 → 配场次票档 → 发布 → 用户购票 → 退款 → 看板数字对得上（销售额 = Σ已支付实付）
- [ ] 移动端 375px 宽：首页/歌曲库/演出详情/播放条不破版
- [ ] 播放兜底：清空某歌 audioUrl → 按钮禁用；MV iframe 被墙 → 外链可用
- [ ] 空态：新账号的订单/收藏/歌单页全部 EmptyState 正常
- [ ] 刷新/分享：带筛选参数的歌曲库 URL 直接打开结果一致

## 4. 性能与安全验收线（M5）

| 项 | 验收线 |
|---|---|
| 下单接口 P95 | 本地并发 50 下 ≤ 500ms |
| 防超卖正确性 | 100 并发抢 10 票：成功订单数恰 = 10，无脏数据 |
| SQL 注入 | 全部查询参数化（JPA/预编译），无字符串拼接 |
| 密码 | BCrypt 存储；登录失败不区分"用户不存在/密码错" |
| JWT | 过期生效；注销后旧 token 自然过期即可（不引入黑名单，注释说明取舍） |
| 日志 | 下单/支付/退款/登录四链路 INFO 必打：userId、orderNo、traceId、耗时；异常 ERROR 带堆栈 |
